# human-do — 委派人类执行

AI 不是万能执行者。当某个环节需要真实世界的手、用户自有账号的权限、或需要人来担责/做主观判断时，AI 硬上只会产出垃圾。这个 skill 给 AI 一个**认怂并转包**的出口：在规划阶段做能力自评，把不该自己做的环节编成一张可验收的「任务卡」交给人类，人做完回报，AI 再继续。

它和另外两种协作姿态不同：

| 模式 | 谁执行 | 何时用 |
|------|--------|--------|
| AskUserQuestion | AI | 只需澄清一个具体选择 |
| HITL 审批 | AI 做，人点头 | 需要人批准/确认 |
| **human-do** | **人做，AI 指挥** | 需要人的手/账号/判断/担责 |

一句话区分：**问选择 → AskUserQuestion；求批准 → 直接确认；求执行 → human-do。**

## 委派阈值（何时调用）

AI 先做能力自评，按以下分类决定是自己上还是委派。

**强制委派 — AI 永远不该自己硬上：**
1. **物理世界动作**：拍照、扫描纸质件、插拔/开关硬件、在真实 GUI 里点击敏感操作。
2. **权限/账号门控**：登录用户自有账号导出数据、授权 OAuth、支付/转账、读取用户私有凭据。
3. **需人担责的动作**：法律签署、代表用户对外做出承诺、删除不可逆的个人数据。

**建议委派 — AI 能做但人更合适：**
4. **主观/审美判断**：配色定调、文案语气、设计取舍——这些"对不对"由人说了算。
5. **本地个人文件高危操作**：配合 personal_files_safety 规则，AI 出任务卡、人执行（扫描/报告 vs 实际删除），不替人动个人目录。

**AI 自己做的（不要委派）：**
信息检索、代码/文本生成、分析、规划、格式转换——这些 AI 擅长，委派给人反而低效。

## 任务卡结构

每次委派输出一张任务卡，四段缺一不可。含糊的卡 = 失败，重写而非发出。

```
## 任务卡 #N：<一句话标题>
背景：为什么做（目的，让人理解意义）
步骤：
  [ ] 1. 具体、无歧义的动作
  [ ] 2. 按顺序，每步可独立验证
  [ ] 3. ...
验收：怎样算"做完了"（可观测的标准）
回报：完成后贴截图 / 回文件名 / 说 done；卡住说 blocked + 卡哪
```

写卡原则：
- **步骤可执行**：人照做不卡壳，不出现"优化一下"这种空话。
- **验收可观测**：写明看到什么结果算完成（文件出现、截图里某状态）。
- **一次一张为主，批量用 #N 编号**；单轮委派不超过 3 张。

## 回报协议

人类做完后按固定格式回报，Agent 据此继续：
- **完成**：`done` + 结果（截图 / 文件路径 / 简短描述）
- **卡住**：`blocked` + 卡在哪、需要什么

Agent 收到 `done` 后**先校验再继续**——对照任务卡验收标准确认真做完了，再推进后续。收到 `blocked` 则重新评估：改步骤、自己找替代方案、或放弃该环节并说明。

## 防滥用规则

human-do 是补漏，不是甩锅。违反以下任一条即属误用：
- **先自己尝试**，仅在确有理由时委派；AI 本可高质量完成的，必须自己做。
- **禁止把"懒得做"包装成"不归我管"**——这是最常见误用。
- 单轮委派 ≤ 3 张任务卡；更多拆批，不要一次砸一堆。
- 任务卡必须可执行、可验收；含糊就重写。
- 能用一个问题澄清的，用 AskUserQuestion，不要发任务卡。
- 需要人审批的，直接确认，不要让人去"执行"。

## 示例

场景：用户要"把上个月银行卡流水整理给我"。
AI 自评：导出流水需登录用户网银（权限门控 #2）→ 强制委派。

```
## 任务卡 #1：导出上月银行流水
背景：需要你账户的上月流水来做对账，只能从你本人网银导出。
步骤：
  [ ] 1. 登录你的网上银行（手机 App 或网页）
  [ ] 2. 进入「账户明细」→ 选上月 → 导出为 CSV 或 Excel
  [ ] 3. 把文件传到当前工作区（如 D:\Data\Projects\MySkill\inbox\）
验收：工作区出现名为 *-流水.csv（或 .xlsx）的文件，时间范围覆盖上月。
回报：done + 文件名；若找不到导出入口说 blocked + 用的哪家银行/哪个端。
```

AI 收到 `done + 流水.csv` 后校验文件存在、月份对，再继续解析。
